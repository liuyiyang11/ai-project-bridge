# V0.3 Research Loop 基础能力

本阶段只增加 experiment task 的最小执行闭环，不改变 V0.2.1 的 Task lifecycle、WorkerQueue、EventBus、MCP contract 或 security model。

## Runtime

```text
TaskSupervisor
└── WorkerQueue
    └── TaskRunner
        ├── CodeTaskHandler       -> RuntimeCodeExecutor
        └── ExperimentTaskHandler -> ExperimentExecutor
```

`experiment-review` 仍走原有兼容入口；新的 `experiment` task 通过 `TaskSupervisor.start_experiment_task(project, command_id)` 进入共享异步 runtime。`command_id` 必须匹配注册项目的 `allowed_commands`，executor 不接受 task 携带的任意 argv、cwd 或路径。

## Public outputs

Experiment executor 将已注册命令的 stdout/stderr 保存到 TaskStore，并在任务目录的 `experiment_bundle/logs/` 保存日志 artifact。项目 `artifact_dirs` 中的有界文件被归一为以下四种 kind：

- `metrics`: `.json`、`.csv`、`.txt`
- `logs`: `.log` 或日志目录中的文件
- `prediction_image`: `.png`、`.jpg`、`.jpeg`、`.webp`
- `confusion_matrix`: 路径或文件名包含 `confusion`

MetricCollector 不执行文件内容，只读取 JSON/CSV/TXT，并输出：

```json
{
  "metric_name": "accuracy",
  "value": 0.9,
  "step": 1,
  "metadata": {"split": "validation"}
}
```

只保存公开执行结果和 artifact metadata，不保存 chain of thought。

## 后续接入 UNetMamba 所需配置

接入具体项目时只需在 ignored 的 `config.local.yaml` 中注册项目 root、能力、训练命令和输出目录；训练脚本及模型代码仍由项目自身提供。例如：

```yaml
projects:
  unetmamba:
    capabilities: [code, experiment]
    root: 'D:/Projects/UNetMamba'
    repo: 'YOUR_NAME/UNetMamba'
    allowed_commands:
      train:
        argv: ['python', 'train.py', '--config', 'configs/train.yaml']
      evaluate:
        argv: ['python', 'evaluate.py', '--config', 'configs/eval.yaml']
    artifact_dirs: ['outputs', 'logs', 'predictions', 'reports']
```

需要由项目侧确定的参数包括训练/评估脚本入口、配置文件相对路径、输出目录、metrics 文件格式以及 prediction/confusion matrix 命名约定。本阶段不实现这些训练脚本，也不绑定 UNetMamba。
